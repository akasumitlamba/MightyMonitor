# Design direction

Applied Anthropic's frontend-design skill after installing it from anthropics/skills, skills/frontend-design.

## First pass

Subject: local connections between physical screens. Audience: users who want a simple download and a clear understanding of current capabilities.

Tokens: chalk #f5f7fa, graphite #172627, cobalt #285cff, mint #b9f2cd, ice #e4edf9, neutral #d7ded5.
Type: Sora for the compact geometric brand and large headings; IBM Plex Sans for readable body and controls.
Layout: a left-aligned purpose statement beside a responsive connected-device illustration, followed by capabilities, an actual milestone sequence, and installer availability.

[ purpose + availability ][ connected devices / mode controls ]
[ three distinct use cases                                  ]
[ engine built -> Linux prototype -> cross-device -> release ]
[ Windows installer | Linux package | Android package        ]
[ practical questions / project links                       ]

Principles: the device relationship is the distinctive visual; status must be honest, installer actions must resolve only to published installer assets, illustrative behavior must be labeled as a concept.

## Critique and revision

The initial draft used uppercase labels before every heading, arbitrary numbered capabilities, colored half-headlines, and arrow-heavy link copy. Those choices did not explain this product. Remove them. Keep numbering only for the real development sequence. Use a cool neutral background tied to the blue/mint icon, one-color purpose-led headlines, and user-triggered motion inside the screen demonstration. Explain unavailable downloads directly without pretending an installer exists.

Keep the original illustration and quiet open layouts; the page is not a dashboard. Respect reduced motion, visible focus, small screens, and real status. No invented performance metrics, testimonials, download counts, or completion percentages.
